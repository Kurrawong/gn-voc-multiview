# Geographical Name Status Types

A single-page HTML and JavaScript viewer for the SKOS vocabulary in `gn-status-types.ttl`.
The layout follows the [ICSM Catalogue](https://icsm.information.qld.gov.au/).

## Run locally

Use Node.js 22 or later:

```sh
npm start
```

Open [http://127.0.0.1:8080](http://127.0.0.1:8080).
The prebuilt `assets/app.js` bundle is included, so dependencies are not required to run the app.
You can also serve this directory with any static HTTP server. Opening `index.html` through `file://` will not
load the vocabulary because it is fetched over HTTP.

## Views and concept details

- **National:** concepts with ICSM as their `schema:creator`, using preferred labels.
- **Jurisdictions:** national concepts plus concepts created by the selected jurisdiction, using matching typed
  alternative labels with preferred-label fallback.
- **All:** every concept, using preferred labels regardless of creator.

The hierarchy reads both `skos:broader` and `skos:narrower`, deduplicates edges, and supports expanding and collapsing
branches. Click a concept label to open its information modal. The modal displays the selected label, remaining labels,
notations, definitions, and abbreviated creators. Identical alternative labels and notations are grouped with their
jurisdiction acronyms in the same order as the View dropdown. Close the modal with Escape, its Close button, or a click
outside it.

## Development

```sh
npm ci
npm run build
npm test
```

- `index.html` and `styles.css`: layout and presentation.
- `app.js`: hierarchy rendering and modal interactions.
- `vocabulary.js`: RDF parsing, creator filtering, label selection, and modal data.
- `vocabulary.test.js`: regression tests for vocabulary and modal behavior.
- `server.js`: local static HTTP server, bound to `127.0.0.1:8080`.
- `assets/app.js`: browser bundle generated by esbuild.

Rebuild after editing JavaScript source. Changes to the Turtle vocabulary are loaded on the next page reload.

## GitHub Pages

The `Publish GitHub Pages` workflow tests and builds the app on every push to `main`, then publishes only the static
page, browser bundle, vocabulary, images, and license notices. It can also be started manually from the Actions tab.

Configure this repository on GitHub:

1. Open **Settings → Pages → Build and deployment** and set **Source** to **GitHub Actions**.
2. Under **Settings → Actions → General**, ensure GitHub Actions and the official `actions/*` actions are allowed.
3. If the `github-pages` environment has deployment branch restrictions, allow `main`. Required reviewers will pause
   deployments until approval; omit that requirement for fully automatic publication.
4. Push `main` to `origin`. Check the workflow in **Actions** for the deployment result and published URL.

No personal access token or repository secret is required; the deployment job uses `GITHUB_TOKEN` with `pages: write`
and `id-token: write`. The expected project URL is
[https://kurrawong.github.io/gn-voc-multiview/](https://kurrawong.github.io/gn-voc-multiview/).
